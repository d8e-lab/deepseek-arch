# Compact Skill — 对话上下文压缩

> 当对话历史过长、上下文接近 token 上限，或用户要求"压缩""compact""总结历史"时激活。
> 目标：把早期轮次压缩为结构化摘要，保留关键信息，降低后续请求的 token 成本，
> 同时不破坏当前任务的连续性与 KV-cache 收益。

---

## 0. 触发时机（必须首先判断）

满足任一即进入压缩流程：

1. **用户明确要求**："压缩一下""compact""把之前的对话总结掉"
2. **上下文接近上限**：消息队列 token 估算 > 上下文窗口的 ~70%（如 128k 窗口 > 90k）
3. **历史轮次过多**：turnCount > 30 且多为工具调用轮次（消息序列膨胀）
4. **模型主动建议**：连续多轮后感觉早期上下文稀释，且后续任务不依赖全部细节

**不触发**：对话较短（< 10 轮）、早期信息仍被高频引用、任务即将完成（压缩收益低）。

---

## Phase 1 — 评估与边界划定

```
□ 统计当前消息队列规模（buildMessages 后的 token 估算）：
    system prompt + environment_info + 全部 turns.messages + 当前消息
□ 决定压缩边界：
    - 保留最近 N 轮完整（建议 N=5~10，覆盖"进行中"的工作）
    - N 之前的轮次 → 压缩为 1 条摘要消息
□ 与用户确认边界（压缩不可逆，必须确认）：
    - 保留轮次数 N
    - 摘要将包含什么（见 Phase 2 格式）
```

**强制产物**：压缩方案（保留 N 轮 + 摘要范围）——向用户展示后等确认。

---

## Phase 2 — 生成摘要

对边界前的所有轮次，用**独立的一次模型调用**（非流式，或复用当前 provider）
生成结构化摘要。**不得**在对话内"口头总结"代替——必须产出可落地的摘要文本。

### 摘要必须包含（逐轮扫描）

| 类别 | 必须保留的信息 |
|------|--------------|
| **用户目标** | 用户最初要解决什么问题、各轮提出的需求（原话要点） |
| **决策** | 已确定的技术方案、被否决的方案及原因 |
| **变更** | 修改/创建了哪些文件（路径+一句话变更）、git 提交/分支 |
| **工具结果** | 关键命令输出、调研结论、浏览器访问的 URL |
| **未完成事项** | 明确标记 ⏳ 的待办、被中断的工作、下一步计划 |
| **约束** | 用户设定的安全/风格/范围限制（如"不要改 X"） |

### 摘要格式（Markdown，控制在 ~500 tokens 内）

```markdown
## 会话摘要（<日期> 前）
### 目标
- ...
### 已决策
- ...
### 变更
- `src/foo.ts`: 做了什么
- commit: xxx
### 关键调研结论
- ...
### ⏳ 未完成
- [ ] ...
### 约束
- ...
```

**遗漏检查**：逐 turn 比对，任何被后续轮次引用的信息不得省略（如"之前改过 X"）。

---

## Phase 3 — 构建压缩后上下文

```
□ 确认摘要无遗漏后：
□ 将边界前的轮次替换为单条摘要消息（role: user 或 system 均可，推荐 user + 标记）
□ 保留最近 N 轮原始 messages（不压缩——正在进行的工具调用/决策需要完整上下文）
□ 摘要作为消息队列的开头（紧跟 system prompt），顺序：system → 摘要 → 最近 N 轮 → 当前
```

**实现路径（任选其一，取决于项目基础设施）**：
- 若有 `/compact` 命令：调用 SessionManager 的压缩接口（内部替换 turns）
- 若无：将摘要**写入会话**（如持久化为一条特殊摘要 turn），后续 buildMessages 自动从摘要开始
- 过渡方案：本轮输出摘要文本 + 提示用户"新会话继续时引用摘要"

**注意 KV-cache**：压缩改变消息前缀，首次压缩后的请求会 cache miss——
这是可接受的代价；压缩后保持前缀稳定（摘要不变）以恢复后续命中。

---

## Phase 4 — 验证

```
□ 确认压缩后消息队列 token 显著下降（记录压缩前后估算值）
□ 抽查摘要中 3 个关键信息点，确认与原对话一致
□ 确认"未完成事项"完整（⏳ 项是后续任务的入口）
□ 向用户说明：压缩范围、保留轮次、摘要保存位置
```

**强制产物**：压缩前后 token 对比 + 未完成事项清单。

---

## 技巧

- **先压缩再干活**：压缩应在任务间隙做（模型空闲或等待用户时），避免打断执行
- **保留工具调用轮次的"结果"而非"过程"**：中间冗长的 shell 输出可省略为结论
- **不要压缩系统 prompt**：environment_info 每次重建，与压缩无关
- **摘要要可"续命"**：写好后设想"下一轮只有这份摘要，能否继续任务"——能，才合格
- **压缩不是删除**：磁盘 turns.json 保留原始记录（压缩只影响请求上下文），可随时回查

---

## 与相关机制的关系

- **KV-cache**：压缩后前缀变化 → 首请求 miss；保持摘要稳定 → 后续命中恢复。收益：压缩省下的 token 通常远超一次 miss 的成本
- **中断轮次**：interrupted 轮次的 messages 需保留（含已完成工具交互），或把关键交互并入摘要
- **subagent 结果**：子代理的结论应并入摘要（原始过程记录在 subagents/ 目录可回查）
- **session 持久化**：压缩建议新增一种 turn 类型（如 `summary` 标记）或在 meta 中记录 `compacted_before_turn: N`，便于追溯
