# Docs Skill — 文档维护规范

> 此 skill 为条件激活：当你触碰 `docs/` 目录下的文件时自动可用。

## 目录结构约定

```
docs/
├── bugs/          # Bug 记录（按日期或问题命名）
├── todo/          # 待办与进度
└── <topic>.md     # 主题文档
```

## 维护规则

1. **与代码同步**：改代码后及时更新对应文档，禁止"代码已改、文档过时"
2. **面向读者**：文档写给接手者，不是写给自己——补全上下文，不写只有自己懂的缩写
3. **引用规范**：提及代码时标注 `<文件路径>:<行号>`
4. **链接相对化**：文档间引用用相对路径，不用绝对路径
5. **新增文档**：命名用 kebab-case（如 `memory-mechanism.md`），并确认在 docs/ 根有索引或导航

## 强制产物

- 文档变更后：`git add docs/` + commit，message 说明"改了什么 + 为什么"
- 结构变更（新增/移动文档）时：同步更新 README 或索引
